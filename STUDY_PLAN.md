# Interview Preparation Plan

Use this sequence at your own pace. It has no calendar dates or assumed completion history. Aim to recognize patterns, explain decisions, handle edge cases, and solve unfamiliar variations.

## Study sequence

| Session | Focus | Work |
| --- | --- | --- |
| 1 | Arrays and HashMaps | All five core questions |
| 2 | Strings and Sliding Window | All five core questions |
| 3 | Two Pointers and Binary Search | All five core questions |
| 4 | Linked Lists, Stacks and Queues | All five core questions |
| 5 | Trees and BST | All five core questions |
| 6 | Graphs and Union Find | All five core questions |
| 7 | Heaps, Intervals and Greedy | All five core questions |
| 8 | Dynamic Programming | All five core questions |
| 9 | Backtracking, Recursion and Tries | All five core questions |
| 10 | Mock interviews | Two timed rounds; review mistakes |
| 11 | Revision | Re-solve weak questions and explain edge cases |

Each topic has five questions. Solve two independently, attempt a harder one, and trace or review the remaining two; repeat the session if needed. Reading an explanation does not count as independently solving a problem.

## Priorities

1. Master Arrays and HashMaps, Strings and Sliding Window, Trees, Graphs, and Two Pointers/Binary Search.
2. Understand all Linked List/Stack/Queue and Heap/Interval/Greedy questions.
3. Master at least three DP and three Backtracking/Trie questions, then cover the rest.

## Focused practice block

| Activity | Minutes |
| --- | ---: |
| Review one pattern | 30 |
| Solve two problems independently | 90 |
| Attempt one harder problem | 45 |
| Explain and dry-run solutions | 30 |
| Review mistakes | 15 |

## Interview routine

| Step | Minutes |
| --- | ---: |
| Clarify inputs, outputs, constraints | 3 |
| Describe brute force | 3 |
| Identify a better pattern and explain why it works | 5 |
| Implement | 20 |
| Dry-run normal and edge cases | 7 |
| Explain complexity and trade-offs | 2 |

The routine totals 40 minutes, leaving discussion time in a 45-minute mock. Practice with hints initially if needed, then repeat without looking at solutions.

## Five mock rounds

Use one main question per round. Treat the follow-up as discussion, not a second mandatory implementation.

| Round | Main question | Follow-up |
| --- | --- | --- |
| 1 | Group Anagrams | How would the signature change for a larger alphabet? |
| 2 | Minimum Window Substring | Explain repeated target characters and empty target handling. |
| 3 | Lowest Common Ancestor | What if a target is absent? |
| 4 | Course Schedule | Return a valid order, or explain how to identify a cycle. |
| 5 | LRU Cache | Discuss concurrency and expiring entries. |

Assess problem understanding, algorithm choice, correctness, complexity, communication, and edge-case coverage. Record the mistake, its cause, and a concrete change for the next attempt.

## Additional preparation

Work through the [five system design prompts](system-design/README.md) using requirements, API, data model, architecture, scaling, failures, and trade-offs. Confirm role-specific expectations with the recruiter.

Prepare truthful STAR stories for the [ten behavioral prompts](behavioral/README.md). Use actual responsibilities and outcomes. Avoid memorizing fictional model answers.
